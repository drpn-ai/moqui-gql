# moqui-gql v0.1.0 (Darpan fork)

The first tagged release of Darpan's fork of moqui-gql, and the first one meant to be pinned in the images
(`MOQUI_GQL_REF`). It turns the public GraphQL endpoint into a read-only API that agents can use for one tenant's
audit runs.

## What a caller gets

- **`auditReport(audit:, date:, period:)`**: one audit's report for one morning (`darpan.audit.report/v1`): whether
  the checks can be trusted, what is open, and every statement by category with its checks and findings.
- **`auditFinding(id:)`**: one finding (`darpan.audit.finding/v1`): its records in each system, evidence,
  diagnosis, how to fix it, how Darpan confirms the fix, and its history.
- **A self-describing schema.** `GET /rest/s1/graphql/sdl` (no key needed) describes every type, field and
  argument; the audit descriptions are the JSON contract's own sentences.

- **`findings(query:, sortKey:, reverse:, first:, after:)`**: the tenant's findings, searched (`audit:`, `statement:`,
  `category:`, `state:`, `period:`, `firstFound:>=`), sorted and paged.
- **`category(id:)` / `statement(id:)`** on a report: one element of an embedded list, by key.

Both roots read the tenant from the API key. A caller cannot name a tenant, another tenant's finding reads as not
found, and there are no mutations.

## Engine changes

- `root-query tenant-param`: a service-backed root receives the request's pinned tenant. A schema that also
  declares that name as an argument is refused when it loads; with no tenant the service is not called.
- `edge kind="embedded"`: a nested object or list read from the parent row, costed as 1 + its contents (no
  per-element fan-out). `field list="true"`: a list of scalars.
- A service-backed root shows a caller only the service's `publicError`; any other error is logged and answered
  `<root> could not be completed`. Errors already on the context are kept aside and restored.
- A service-backed root can take `query`, `sortKey` and `reverse`; an embedded list edge can offer one element by key.
- `printSdl` task; sort-enum values and id arguments describe themselves.
- The unset source-key and lookup-key edge attributes are gone, and the audit report no longer has `extendedThru`.
- `description` (attribute or child element) on `gql-type`, `field`, `edge`, `root-query` and `arg`, printed in the
  SDL. Generated connection types, sort enums and paging arguments describe themselves.

## API keys

- `list#ApiKeys`, `disable#ApiKey`, `rotate#ApiKey` beside `create#ApiKey`; super-admin only, each gating itself.
  None returns or logs a key or its digest. Rotation returns the new key once and gives the old key a grace of
  0-1440 minutes (default 60).
- `resolve#ApiKey` writes `lastUsedDate` at most once a minute per key (it wrote on every request).

## Tests

- `DarpanSuite` (25 tests, pure engine units and the Darpan additions) is the default test task. The inherited
  OMS-era `MoquiSuite` needs a MySQL OMS database and runs only with `-PomsSuite`.
- Test dependencies follow the framework (Spock 2.4 for Groovy 5, JUnit Platform 6). The previous Spock 2.1 for
  Groovy 3 left the test classpath unresolvable.
- Behaviour that needs Darpan's entities runs in the darpan component's suite: `AuditGraphQlSmokeTests`,
  `GraphQlSchemaDescriptionTests`, `GqlApiKeyManagementTests`.
